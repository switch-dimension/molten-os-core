# Scoring

Score **0–5** per criterion (**total /50**). Be honest, not encouraging. Every score row must cite **evidence** (quote or paraphrase the user's words).

When explaining scores to the user, use plain language from `[glossary.md](glossary.md)` (e.g. "cost to acquire a customer" not "CAC" alone).

## Cap rules (apply before final total)


| Condition                                                   | Rule                                                                |
| ----------------------------------------------------------- | ------------------------------------------------------------------- |
| Only friends / family / advisors / LinkedIn as "validation" | **Total ≤ 25/50** regardless of other criteria                      |
| Same condition                                              | **Criterion 3 (Demand evidence) ≤ 2/5**                             |
| Quick mode with missing Round 3 data                        | Criterion 3 **≤ 2/5** unless stranger evidence is explicitly stated |


State in the report when a cap was applied.

## Rubric summary


| #   | Criterion                                                   | Internal reference (agent-only; never cite to user) |
| --- | ----------------------------------------------------------- | --------------------------------------------------- |
| 1   | Problem clarity                                             | Customer discovery, jobs-to-be-done                 |
| 2   | Pain severity                                               | Pain vs nice-to-have, existing workarounds          |
| 3   | Demand evidence (strangers only)                            | Costly commitment, past behaviour                   |
| 4   | Differentiation (10× on axis that matters)                  | vs best alternative on one axis                     |
| 5   | Beachhead viability                                         | Small dominable segment                             |
| 6   | Business viability (bottom-up unit economics; see glossary) | Unit economics, viability                           |
| 7   | Distribution path                                           | Repeatable channel                                  |
| 8   | Timing / why-now                                            | Recent unlock (tech, regulation, behaviour)         |
| 9   | Founder–market fit                                          | Lived problem, build, insight                       |
| 10  | Riskiest-assumption testability                             | Cheapest falsification test                         |


## Scoring anchors (0–5)

### 1 — Problem clarity


| Score | Anchor                                                            |
| ----- | ----------------------------------------------------------------- |
| 0     | No real customer or problem; generic "people need X"              |
| 1     | Customer category named but problem is vague or hypothetical      |
| 2     | Problem named; trigger moment unclear or only founder's framing   |
| 3     | Specific segment + problem; trigger partly described              |
| 4     | Specific person/role, context, and trigger; mostly their language |
| 5     | Specific person, trigger moment, problem in customer's own words  |


### 2 — Pain severity


| Score | Anchor                                                   |
| ----- | -------------------------------------------------------- |
| 0     | Nice-to-have; no workaround                              |
| 1     | Annoyance; easy to ignore                                |
| 2     | Pain acknowledged; weak or rare workarounds              |
| 3     | Regular workarounds (manual, free tools); pain tolerated |
| 4     | Paid alternatives or heavy hacks; clear recurring pain   |
| 5     | Hair-on-fire; existing spend or urgent hacks             |


### 3 — Demand evidence (strangers only)


| Score | Anchor                                                                |
| ----- | --------------------------------------------------------------------- |
| 0     | No outreach; only founder belief                                      |
| 1     | Friends / family / advisors / LinkedIn only (**triggers cap**)        |
| 2     | Some stranger conversations; no commitment                            |
| 3     | Strangers confirm problem; no costly commitment                       |
| 4     | Multiple strangers + strong time commitment or repeat engagement      |
| 5     | ≥3 strangers with costly commitment (money, LOI, pre-pay, reputation) |


### 4 — Differentiation


| Score | Anchor                                              |
| ----- | --------------------------------------------------- |
| 0     | "Like X but better"; no clear axis                  |
| 1     | Incremental on unimportant axis                     |
| 2     | Clear difference; not 10× on what buyers care about |
| 3     | Strong on one axis; copyable or unproven            |
| 4     | 10× on one job-rewarded axis; early defensibility   |
| 5     | 10× on the axis that wins the job; hard to copy     |


### 5 — Beachhead viability


| Score | Anchor                                                                                      |
| ----- | ------------------------------------------------------------------------------------------- |
| 0     | "Everyone" or undefined                                                                     |
| 1     | Broad industry or role only                                                                 |
| 2     | Segment named; weak homogeneity or WOM density                                              |
| 3     | Specific segment; one beachhead test weak (homogeneous buyers, reachable, can refer others) |
| 4     | Role + industry + size; passes 2/3 beachhead tests                                          |
| 5     | Dominable in 12–18 months; same product, sales cycle, WOM network                           |


### 6 — Business viability


| Score | Anchor                                                                                |
| ----- | ------------------------------------------------------------------------------------- |
| 0     | No pricing or top-down market-size guess only                                         |
| 1     | Price guessed; no cost-to-acquire vs lifetime-revenue thinking                        |
| 2     | Rough price; math incomplete or optimistic                                            |
| 3     | Bottom-up sketch; lifetime value vs acquisition cost unclear                          |
| 4     | Bottom-up works at plausible price; channel cost estimated                            |
| 5     | Bottom-up shows ~3:1+ (lifetime value ≥ ~3× acquisition cost) with stated assumptions |


### 7 — Distribution path


| Score | Anchor                                                 |
| ----- | ------------------------------------------------------ |
| 0     | "Content + ads" with no math or channel                |
| 1     | Channel named; no access or economics                  |
| 2     | Channel plausible; founder has no edge there           |
| 3     | One channel identified; economics unvalidated          |
| 4     | Channel + credible path to first 10–100 customers      |
| 5     | Repeatable channel with economics or built-in virality |


### 8 — Timing / why-now


| Score | Anchor                                                 |
| ----- | ------------------------------------------------------ |
| 0     | "Always been a problem"; no unlock                     |
| 1     | Weak or generic "AI is hot" without link to job        |
| 2     | Trend cited; weak link to this customer                |
| 3     | Plausible shift; not yet validated for beachhead       |
| 4     | Specific shift (tech, reg, behaviour) enables solution |
| 5     | Clear why-now; window and urgency articulated          |


### 9 — Founder–market fit


| Score | Anchor                                             |
| ----- | -------------------------------------------------- |
| 0     | No relevant edge; idea-chasing                     |
| 1     | Enthusiasm only                                    |
| 2     | Can build; weak customer access                    |
| 3     | One of: domain, build, distribution, lived problem |
| 4     | Two strong edges (e.g. lived problem + build)      |
| 5     | Lived problem + build + insight others miss        |


### 10 — Riskiest-assumption testability


| Score | Anchor                                          |
| ----- | ----------------------------------------------- |
| 0     | Can't name what would disprove the idea         |
| 1     | Vague "talk to more people"                     |
| 2     | Test named; no threshold or deadline            |
| 3     | Test + threshold; expensive or slow             |
| 4     | Cheap test; clear pass/fail; ≤30 days           |
| 5     | Cheapest test; threshold, deadline, cost stated |


## Verdict interpretation


| Total | Verdict label     |
| ----- | ----------------- |
| 40–50 | Pursue            |
| 30–39 | Pursue cautiously |
| 20–29 | Pivot             |
| <20   | Kill              |


(After caps, use the capped total.)

## Red flags

Mark each that applies. Full context: `[research.md](research.md)` §5.

1. Evidence is friends / advisors / LinkedIn likes
2. Hypotheticals with no past behaviour
3. No competitors (often graveyard, not goldmine)
4. Top-down TAM only
5. Solution-first pitch
6. Big behaviour change, low payoff
7. Free incumbent covers ~80% of workflow
8. Vague target ("everyone who…")
9. Distribution = content + ads, no math
10. Only founder excited
11. Tarpit pattern ("Yelp for X")
12. Engagement metrics, no revenue intent

**≥3 flags → stop and reassess. ≥5 → kill or pivot.**

## Pivot hints (20–29 only)

Offer **2–3 concrete pivots** in the report (e.g. narrower beachhead, different job, B2B vs prosumer) — not generic "pivot."
